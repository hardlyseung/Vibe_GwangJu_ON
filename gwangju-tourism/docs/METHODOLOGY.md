# AI 협업 개발 방법론

이 서비스는 AI 코딩 도구로 만들었다. 이 문서는 **무엇을 만들었는가**가 아니라
**어떤 절차로 AI와 함께 만들었고, AI가 만든 것을 어떻게 검증했는가**를 기록한다.

---

## 1. 왜 절차가 필요한가

AI 코딩 도구는 요청하면 코드를 만들어 준다. 문제는 그 코드가 **그럴듯하게 틀릴 수 있다**는 점이다.
이 프로젝트에서 실제로 발생한 사례가 있다.

> AI가 초기 샘플 데이터를 만들 때, 광주 관광지의 위도·경도를 그럴듯한 숫자로 채워 넣었다.
> 형식은 완벽했고 값의 범위도 광주 근처였다. 검증 절차가 없었다면 그대로 지도에 찍혔을 것이다.

그래서 이 프로젝트는 "AI에게 시키고 결과를 받는" 방식이 아니라, **AI의 출력을 구조적으로 의심하는 절차**를 세웠다.
아래 다섯 가지가 그 절차다.

---

## 2. 스펙 우선 (Spec-first)

코드를 쓰기 전에 실행 명세를 먼저 작성했다. 다만 전통적 PRD가 아니라, 마감이 정해진 작업에 맞춰
**세 가지만 답하는 문서**로 축약했다.

1. 무엇을 만들고 무엇을 **안 만드는가** (스코프 고정)
2. 어떤 순서로 만들고, **무엇이 보이면** 그 단계가 끝난 것인가 (완료 판정)
3. 막히면 어디를 보는가 (장애 플레이북)

핵심은 **스코프 동결 규칙**이다. *"마감 24시간 전부터는 기능을 추가하지 않는다.
그 이후 떠오른 아이디어는 코드가 아니라 발표자료의 향후 확장 항목으로 보낸다."*

AI는 요청하면 무엇이든 만들어 주기 때문에, 기능을 늘리는 데 마찰이 없다.
그래서 마찰을 인위적으로 만들어야 한다.

---

## 3. 컨텍스트 엔지니어링

AI 세션은 매번 맥락을 잃는다. 같은 설명을 반복하면 설명이 조금씩 달라지고, 결과물도 갈라진다.
그래서 프로젝트의 판단 기준을 저장소 안의 규칙 파일(`CLAUDE.md`)에 고정했다.

여기에 담은 것은 코드 스타일이 아니라 **이 프로젝트에서 무엇이 금지인가**이다.

- 데이터에 없는 사실을 지어내지 않는다
- `TODO` 값을 사용자나 모델에게 노출하지 않는다
- 5·18 관련 서술은 공식 자료 외 출처를 쓰지 않는다
- 만료되는 무료 자원에 의존하지 않는다
- 프레임워크를 도입하지 않는다

규칙을 파일로 고정하니 세션이 바뀌어도 같은 판단이 유지됐다.

---

## 4. 아키텍처 의사결정 기록 (ADR)

"AI가 추천해서" 정한 것은 없다. 각 선택에는 **기각한 대안과 기각 사유**가 있다.

| # | 결정 | 기각한 대안 | 사유 |
|---|---|---|---|
| 01 | Direct-Context 주입 | RAG · 벡터 DB | 18행 정형 데이터에 임베딩 검색은 과잉이다. 전문을 그대로 넣으면 검색 실패로 인한 누락 위험이 0이 된다 |
| 02 | 순수 HTML/CSS/JS | Next.js · React | 작성자가 프레임워크 미경험. 학습 비용이 남은 기간을 초과한다 |
| 03 | Vercel | GitHub Pages | 정적 호스팅은 서버리스 함수를 실행할 수 없어 AI 연동 구조 자체가 성립하지 않는다 |
| 04 | AI Studio 무료 티어 | GCP 체험판 크레딧 | 크레딧은 만료된다. 2027-03-31까지 운영해야 하는 공모 조건을 위반한다 |
| 05 | 카카오맵 | 구글 지도 | 국내 도로명주소 정확도. 결제수단 등록 불필요, 초과 시 과금이 아닌 차단 |
| 06 | 정적 JSON | PostgreSQL 등 | DB가 없으면 만료·백업·다운타임 이슈가 원천적으로 발생하지 않는다 |

01번이 이 프로젝트의 성격을 결정했다. 일반적인 AI 관광 챗봇은 웹 전반을 학습한 모델이 답한다.
이 서비스는 **선택된 거점의 공식 자료 안에서만** 답한다. 좁지만 틀리지 않는다.

---

## 5. 환각 방지 3중 방어

"AI가 지어내지 않게 한다"는 목표를 프롬프트 한 줄로 해결할 수 없다. 세 계층으로 나눠 막았다.

**① 데이터 계층 — 근거 자료의 무결성**

미작성 필드는 `TODO` 문자열로 남아 있다. 이걸 프롬프트에 그대로 넣으면
모델은 `"TODO: 배향 인물 검증 필요"` 를 사실로 취급한다.
그래서 프롬프트를 조립할 때 채워진 필드만 통과시킨다.

```js
function isFilled(value) {
  return typeof value === "string" && value.trim() !== "" && !value.trim().startsWith("TODO");
}
```

근거가 될 만한 내용이 아예 없는 거점은 **모델을 호출하지 않고** 바로 "확인되지 않았습니다"로 답한다.
호출 비용도 아끼고, 환각의 여지 자체를 없앤다.

**② 프롬프트 계층 — 제약과 거절 문구**

주어진 자료 밖은 답하지 말고, 못 답할 때 쓸 문장까지 지정한다.
거절 방법을 열어두면 모델은 거절 대신 추측을 택한다.

**③ 응답 계층 — 출처 표시와 차단 처리**

모든 답변에 데이터 출처와 기준일을 함께 표시한다.
안전 필터에 걸려 응답이 비는 경우(5·18 같은 민감한 역사 주제에서 발생할 수 있다)도
오류가 아니라 현장 해설사 안내로 처리한다.

## 6. 실패 모드 우선 설계

기능을 다 만든 뒤 예외를 처리하는 대신, **예상 장애를 먼저 문서로 쓰고 그것을 코드로 옮겼다.**
장애 플레이북에 증상·원인·조치를 표로 정리한 뒤, 각 항목을 코드에 반영했다.

실제로 겪은 것과 미리 막은 것이 섞여 있다.

| 장애 | 발견 시점 | 코드에 반영된 대응 |
|---|---|---|
| CSV 한글 깨짐 (EUC-KR) | 실제 발생 | 변환기가 인코딩을 자동 판별 |
| 카카오 `403 OPEN_MAP_AND_LOCAL` | 실제 발생 | 스크립트가 원인과 해결 절차를 직접 안내하고 즉시 중단 |
| 원본 CSV의 자치구 오류 | 실제 발생 | 도로명주소 기준으로 정정, 근거를 데이터에 기록 |
| 지도 SDK 로드 실패가 페이지 전체를 중단 | 사전 차단 | 지도를 마지막에 초기화, 실패해도 나머지 기능 유지 |
| 안전 필터로 빈 응답 | 사전 차단 | 차단 사유를 감지해 안내 문구로 대체 |
| 환경변수 등록 후 재배포 누락 | 사전 차단 | 문서와 오류 메시지에 명시 |
| 지오코딩이 엉뚱한 좌표 반환 | 사전 차단 | 광주 행정경계 밖 결과를 자동 검출 |

플레이북을 먼저 쓴 덕분에, 코드를 짤 때 "이건 어떻게 실패하지"를 이미 알고 있었다.

## 7. AI 출력 검증

AI가 만든 것을 그대로 신뢰하지 않기 위해 세 가지를 했다.

**교차 검증.** 원본 CSV의 `소재지` 컬럼과 `도로명주소`를 대조했더니 5개 행이 어긋났다
(소재지는 남구, 주소는 북구). AI가 데이터를 정리하는 과정에서 그냥 넘어갈 수 있었던 부분이다.
사람이 두 컬럼을 비교했기 때문에 발견했고, 정정 근거를 데이터에 기록해 화면에 공개했다.

**기계적 검증.** 눈으로 확인할 수 없는 것은 코드가 검사하게 했다.
지오코딩 결과가 광주 행정경계 안에 있는지 자동으로 확인하고, 벗어나면 수동 확인 대상으로 표시한다.

**모른다고 말하기.** AI에게 해설 내용을 채우게 하지 않았다.
검증되지 않은 역사적 서술은 `TODO` 로 남기고, 공식 자료로만 채우기로 했다.
특히 5·18 관련 두 곳은 민감한 역사이므로 추측을 일절 배제했다.

빈칸을 남기는 것이 그럴듯한 오답보다 낫다는 판단이다.

---

## 8. 정리

이 프로젝트에서 AI는 **타이핑을 대신해 준 도구**였지, 판단을 대신해 준 주체가 아니었다.

- 무엇을 만들지, 무엇을 자를지 → 사람이 스코프로 고정
- 어떤 구조로 만들지 → 사람이 대안을 기각한 근거를 남김
- 무엇이 사실인지 → 공식 데이터로 제한, 없으면 빈칸
- 어디서 실패할지 → 먼저 문서로 쓰고 코드로 옮김
- 결과가 맞는지 → 교차 검증과 자동 검사

AI 활용의 성숙도는 **얼마나 빨리 만들었는가**가 아니라
**AI가 틀렸을 때 그것을 잡아낼 장치를 갖췄는가**로 판단해야 한다고 본다.
